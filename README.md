# 💣 지뢰찾기

> 자세한 실습 절차는 [guide.md](./guide.md)를 참고하세요.

## 게임 소개

별도의 설치 없이 웹 브라우저에서 바로 즐길 수 있는 **10×10 격자 기반 클래식 지뢰찾기 웹 게임**입니다. 100개의 칸 속에 무작위로 숨겨진 **15개의 지뢰**를 피해 모든 안전 칸을 열면 승리합니다.

- **좌클릭 (칸 열기)**: 선택한 칸을 열어 주변 8방향에 인접한 지뢰 개수(`1`~`8`)를 확인합니다. 주변 지뢰가 `0`개인 빈 칸을 열면 인접한 안전 영역이 연쇄적으로 자동 오픈됩니다.
- **우클릭 (깃발 표시)**: 지뢰가 숨어 있을 것으로 예상되는 칸에 깃발(`🚩`)을 꽂거나 해제하며, 상단 상태바에서 남은 지뢰 수를 실시간으로 확인할 수 있습니다.
- **승패 조건**: 지뢰를 제외한 **85개의 안전 칸을 모두 열면 클리어(`🎉 클리어!`)**, 지뢰를 클릭하면 모든 지뢰 위치가 공개되며 **게임 오버(`💥 게임 오버!`)**가 됩니다.

## 어떻게 만들었나요

1. **PRD 작성**: 무작정 코드를 생성하기 전에 게임의 핵심 규칙, 보드 데이터 구조(`mine`, `revealed`, `flagged`, `count`), 셀별 상태 정의, 예외 처리 조건(우클릭 기본 메뉴 차단, 깃발 칸 클릭 방지, 게임 종료 후 보드 조작 잠금)을 문서로 먼저 정리했습니다.
2. **Plan 확인·보완**: 작성한 PRD를 바탕으로 `index.html`, `style.css`, `script.js` 3개 파일의 역할 분담과 구현 순서를 검토하고, 재귀 탐색 시 배열 범위 초과 방지 및 모바일 화면 레이아웃 보완 사항을 계획에 반영했습니다.
3. **Agent 구현**: 확정된 계획과 PRD 기준에 맞춰 외부 라이브러리 없는 순수 Vanilla JS와 Pure CSS로 코드를 구현하고, 체크리스트 항목별로 동작을 검증했습니다.

## freeform 버전과 비교했을 때

- **`freeform` 버전**: 짧은 한 줄 프롬프트로 빠르게 프로토타입을 만들 수 있었지만, 숫자 `6`~`8`의 색상 정의가 빠져 있거나 게임 종료 후에도 셀 호버 효과가 남아 있는 등 세부적인 UI 상태와 예외 처리가 단순했습니다.
- **`prd` 버전**: 데이터 구조와 예외 상황, 반응형 기준을 사전에 명시하고 구현한 덕분에 함수별 역할(`placeMines`, `calculateAdjacentMines`, `revealCell`, `checkWin`)이 명확하게 분리되고 버그 없이 안정적으로 동작했습니다. 기능 완성도와 코드 유지보수성 모두 `prd` 버전이 훨씬 뛰어나 최종 버전으로 선택했습니다.

## 커스터마이징한 부분

- **숫자별 시인성 강화**: 인접 지뢰 개수 `1`부터 `8`까지 모두 직관적으로 구분할 수 있도록 개별 색상 클래스(`.c1` ~ `.c8`)를 정의했습니다.
- **게임 종료 시 시각적 피드백 개선**: 게임이 끝나면 보드에 `.game-over` 클래스를 부여해 닫힌 칸의 마우스 호버 강조와 포인터 커서를 비활성화하여 조작이 종료되었음을 명확히 표시했습니다.
- **모바일 화면 대응 및 오작동 방지**: `420px` 이하의 좁은 화면에서도 10×10 격자가 깨지지 않도록 셀 크기를 자동 조절하는 반응형 스타일(`@media (max-width: 420px)`)과 빠른 클릭 시 텍스트가 드래그되지 않도록 `user-select: none`을 적용했습니다.
- **시맨틱 마크업 및 접근성**: `<main>`, `<header>`, `<section>` 시맨틱 태그와 `role="grid"`, `aria-live="polite"` 속성을 추가해 구조적 완성도를 높였습니다.
